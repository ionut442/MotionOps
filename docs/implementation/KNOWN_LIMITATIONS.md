# MotionOps Known Limitations

- Context7 was requested for documentation lookup, but no Context7 callable tool was exposed in this Codex session. Official Figma documentation was used as fallback.
- Native Figma runtime read evidence for P0-006 is durable for run `p006-mrin2zvh-ac0f05`. P0-007 retained live run `p007-mriq1s7l-2b2f3c` completes the manual-track replacement investigation: track IDs were stable, but edited timing keyframe IDs may regenerate and easing readback may contain additional normalized fields. Dynamic-page scanning and component/instance write boundaries remain unverified.
- P0-008 live run `p008-mriu1fap-25c85d` conclusively classifies style reapply/update as partial/unsafe: direct `applyAnimationStyle` reapply duplicates style instances, while remove-by-applied-instance then reapply-by-available-style works for S06. Product style writers must not rely on update-in-place behavior.
- P0-009 live run `p009-mrivc1j7-56e68c` proves timeline duration writes are supported with warning. Figma accepted a timeline duration below the final keyframe without clamping or rejecting; derived animation readback mirrors the shorter timeline duration. P0-009 does not verify undo grouping.
- P0-010 live run set `p010-mriz*` proves mixed undo support. U01 requires Strategy C (`commitUndo() -> write`); U03/U05 are supported-with-warning because native Redo did not restore the applied style/mixed state; U06 separate actions require two Undo steps and one Redo after two Undos does not restore the final state; U08 proves `triggerUndo()` rollback for a controlled partial failure. There is still no plugin-side redo API in installed typings.
- P0-011 component/instance behavior is implemented as a live investigation harness, but retained local full-run manifests are rejected because at least one case ended ERROR. Accepted retained manifests are single-case runs only. Do not mark P0-011 DONE from this local evidence without a newer accepted full manifest.
- P0-012 component-property behavior is runtime-conclusive for focused accepted run `p012-mrj6qxvi-217610`: CP09 BOOLEAN component-property writes through `setProperties` are supported-with-warning, plugin-triggered Undo is partial because target/sibling re-reads become stale/missing, CP01/CP02 are read-only property-API findings, and CP08 is unsupported/not-exposed. Broader component-property kinds remain unsupported or read-only until new accepted evidence exists.
- P1-012 production verification compares normalized expected postconditions against fresh normalized actual snapshots. It intentionally does not implement stale-data detection, fingerprint blocking, undo orchestration, transaction planning, batch edits, Inspector logic, UI, or live Figma evidence reruns.

- P1-013 stale-data detection is a pre-write guard layer only. It captures operation-specific normalized projections, re-reads through the production adapter, and returns current/stale/unverifiable without mutating the document, rescanning, rebasing, applying writes, or adding UI.
- P1-013 separates diagnostic snapshot IDs from semantic fingerprints. Snapshot ID equality is never freshness proof; changed snapshot IDs with identical relevant state remain current.
- P1-013 intentionally treats unknown unrelated beta fields as outside the guard projection. Unknown relevant beta fields, such as changed unknown easing payloads that cannot be safely compared, return `unverifiable` instead of a false current/stale claim.
